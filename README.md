## 📌 주요 구현

### 1. 서버 전투 판정

- 캐릭터마다 다른 스킬 범위와 타격 시점을 서버에서 처리하기 위해 히트박스의 모양, 크기, 오프셋, 활성 프레임을 데이터로 관리. 캐릭터와 스킬 키를 기준으로 데이터를 조회해 판정 객체 생성.
- 원형 범위는 중심 사이의 거리와 양쪽 반지름으로 충돌 검사. 방향이 있는 사각형과 직선형 범위는 대상 위치를 전방 및 우측 축에 투영하고, 범위 안의 최근접점과 대상 중심 사이 거리를 비교해 대상 반지름까지 판정에 반영.
- 부채꼴 범위는 거리와 방향각을 검사하고 경계 방향과 대상 반지름을 비교. 캐릭터 회전에 따라 로컬 오프셋을 변환해 스킬 판정 위치 조정.
- 시작 프레임과 종료 프레임을 FPS 기준 시간으로 환산해 히트박스의 활성 시각 설정. 판정 구간에만 충돌을 검사하고, 사용 완료 또는 유지 시간 종료 시 제거하도록 수명 관리.
- 히트박스에 피격 대상 ID를 기록해 같은 공격의 중복 타격 제한. 사망과 대상 지정 불가 상태를 검사하고, 팀 정보와 스킬의 아군 적중 조건에 따라 적용 대상 구분.
- 적중 시 적용할 효과를 캐릭터, 스킬, 레벨별로 분류하고 충돌 결과에 연결. 시전자와 피격 대상 등 효과의 적용 주체를 구분해 피해와 상태 효과 처리.

### 2. 씬 로딩 및 패킷 처리 동기화

- 게임 씬이 준비되기 전에 생성, 이동, 상태 변경 패킷이 도착하면 필요한 오브젝트를 찾지 못하는 문제 발생. 게임용 패킷 핸들러에서 준비 상태를 먼저 검사하고, 준비 전에는 처리 콜백을 큐에 보관하도록 구성.
- 씬 로딩 이벤트만으로 준비 완료를 판단하던 방식에서 비동기 맵 생성 완료를 기준으로 처리하도록 변경. GameScene에서 맵 생성을 기다린 뒤 OnSceneReady를 호출해 실제 초기화 흐름과 패킷 처리 시점 연결.
- 준비 완료 후 대기 콜백을 등록 순서대로 실행하고 기존 패킷 핸들러로 다시 전달. 로딩 중 수신한 패킷을 버리지 않고 게임 씬에서 이어서 처리하도록 구현.
- 본인 플레이어 초기화에 의존하는 다른 플레이어의 생성 작업은 별도 대기 큐로 관리. 씬 준비와 플레이어 준비를 구분해 생성 순서에 따른 의존성 처리.
- 생성 요청 시 오브젝트 ID의 등록 여부를 검사해 중복 생성 방지. 서버 입장 처리도 플레이어 등록 성공 여부를 확인한 뒤 초기화하도록 보완해 중복 입장에 따른 재초기화 제한.
- 씬 준비가 끝난 뒤에도 매 패킷마다 콜백을 만들던 경로를 분리. 준비 상태를 먼저 확인하고, 대기가 필요한 경우에만 콜백을 생성해 불필요한 할당 축소.

### 3. 충돌 대상 리스트 재사용 및 수명 관리

- 활성 히트박스를 검사할 때마다 피격 대상 리스트를 새로 생성하던 구조를 타입별 리스트 풀로 변경. 검사 함수 진입 시 리스트를 대여하고, 히트박스마다 내용을 비워 다음 판정에 재사용.
- 플레이어와 몬스터 등 대상 타입에 따라 풀을 분리하고, 반환 시 대상 참조만 제거해 내부 배열의 용량 유지. 반복되는 충돌 검사에서 리스트 객체와 내부 배열의 재할당 부담 축소.
- 검사 중 예외가 발생하더라도 대여한 리스트가 반환되도록 try/finally 적용. 풀의 대여와 반환 구간에 잠금을 두어 여러 호출에서 같은 리스트가 동시에 대여되지 않도록 처리.
- 충돌 결과를 Room 작업 큐에 전달하면 실제 콜백 실행 전에 검사 리스트가 비워지거나 다른 히트박스에 재사용될 수 있음. 지연 실행 작업에는 별도 리스트를 대여해 대상 목록을 복사하고 전달.
- 지연 작업용 리스트는 큐 등록에 실패하면 즉시 반환하고, 등록에 성공하면 콜백 실행이 끝난 뒤 반환. 충돌 검사와 지연 작업의 사용 수명을 나누어 리스트 재사용 중 대상 목록이 바뀌는 문제 방지.

### 4. 아비게일 전투 시스템

- Q의 첫 타격과 후속 타격을 서로 다른 판정 데이터로 구성하고, 스킬 키의 연결 관계에 따라 후속 히트박스를 함께 등록. 각 판정의 활성 프레임으로 연속 타격 시점 구분.
- E는 시전 거리와 마우스 주변의 유효 적을 검사해 대상 선택. 대상 이동과 피해 처리를 연결하고, 표식 제거 결과를 확인해 표식이 있던 경우에만 E 쿨타임 초기화.
- 패시브 준비 여부에 따라 일반 공격과 강화 공격을 구분. 강화 공격의 애니메이션과 추가 사거리를 적용하고, 적중 시 패시브 쿨타임을 시작하면서 추가 피해와 방어력 감소 효과 연결.
- W의 적중 대상 수를 보호막 계산에 전달하고, 기본 수치와 스킬 증폭 계수에 대상 수에 따른 증가율 및 상한을 반영. 보호막의 소모와 만료를 관리하고 변경된 값을 클라이언트 체력 UI에 전달.
- 스킬별 중단 가능 시점을 두어 동작 전체가 끝나기 전에도 허용된 구간부터 후속 행동을 받을 수 있도록 처리. 경과 시간에 따라 중단 가능 상태를 갱신하고 클라이언트에 전달.
- Q의 후속 공격과 R의 궤적 및 폭발처럼 단계가 나뉜 연출은 서버의 경과 시간과 실행 플래그로 제어. 재생 및 정지 메시지를 클라이언트 이펙트 처리에 연결해 스킬 진행과 종료에 맞춰 연출 관리.

### 5. 팀 시야 및 와드 표시 제어

- 일반 시야, 부쉬 내부 판정, 표식의 시야 공유가 서로 다른 경로로 표시 상태를 변경하므로, 부쉬 내부 대상과 와드의 노출 조건을 구분해 기존 팀 시야 처리에 연결.
- 부쉬 내부의 충돌체에서 아군 와드 존재 여부와 적 와드 목록을 확인. 아군 와드가 있으면 부쉬 내부 적의 노출 조건에 반영하고, 적 와드는 아군 플레이어나 와드로 시야를 확보한 경우에 표시하도록 구성.
- 아비게일 표식 등 서버에서 전달한 시야 공유 대상은 부쉬 내부에서도 노출되도록 판정에 반영. 일반 부쉬 은폐 조건과 스킬에 의한 시야 확보 조건을 함께 처리.
- 일반 시야 갱신이 부쉬 전용 와드 표시를 덮어쓰지 않도록 부쉬 안팎을 구분. 부쉬 내부에서는 별도로 계산한 노출 상태를 적용하고, 외부에서는 일반 가시 여부에 따라 갱신.
- 와드의 Renderer와 수명 UI를 함께 제어해 본체가 숨겨진 상태에서 UI만 남는 표시 불일치 방지. 팀에 따른 와드 UI 색상도 구분해 아군과 적군 식별.
